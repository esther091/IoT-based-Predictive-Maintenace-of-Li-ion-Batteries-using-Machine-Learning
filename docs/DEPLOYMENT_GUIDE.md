# Deploying online (Render + Neon)

The backend and the dashboard run on Render, the database on Neon. The same
code still runs locally with `start_system.bat` when none of the settings below
is set.

| Setting | Where | Value |
|---|---|---|
| `DATABASE_URL` | Render, battery-api | Neon connection string (`postgresql://...`) |
| `API_KEY` | Render, battery-api | generated by Render; copy it into `secrets.h` |
| `BACKEND_URL` | Render, battery-dashboard | `https://<battery-api address>.onrender.com` |

## 1. Neon (database)
1. Create a project, then copy the connection string from **Connect**
   (it starts with `postgresql://` and ends with `?sslmode=require`).
2. Keep it private: it contains the database password.

## 2. Render (backend and dashboard)
1. **New > Blueprint**, connect GitHub and choose this repository.
   Render reads `render.yaml` and proposes two services: `battery-api` and
   `battery-dashboard`.
2. When asked for `DATABASE_URL`, paste the Neon connection string.
3. When asked for `BACKEND_URL`, enter `https://battery-api.onrender.com`
   (if Render shows a different address for battery-api after it is created,
   correct `BACKEND_URL` under battery-dashboard > Environment).
4. Click **Apply**. The first build takes several minutes.
5. Check `https://<battery-api address>/health` in a browser: it should show
   `"models_loaded": true`.
6. Open the battery-dashboard address: this is the web app link.
7. Under battery-api > Environment, reveal and copy the value of `API_KEY`.

## 3. ESP32
In `firmware/esp32_firmware_v2/secrets.h` set:
```c
const char* SERVER_URL = "https://<battery-api address>.onrender.com/readings";
#define API_KEY "<the API_KEY value from Render>"
```
Upload the firmware with the Arduino IDE. The ESP32 needs a WiFi network with
internet access (for example a phone hotspot with mobile data).

## Notes
- Free Render services sleep after about 15 minutes without requests and take
  up to a minute to wake. Open the dashboard a minute before a demonstration.
  While the ESP32 is sending readings every 5 s, the backend stays awake.
- A redeploy or wake-up clears a discharge in progress; start tests after the
  backend is awake.
- To go back to local mode, restore the laptop address in `secrets.h`, leave
  `API_KEY` empty, and run `start_system.bat`.
